1 · Delivery pipeline

From commit to production

  1. A developer pushes a commit. The repository records it and fires a webhook.
  2. CI builds an image and runs the test suite against it, in a clean container every time.
  3. A failing check goes straight back to the author, with the log. Nothing moves on.
  4. A passing image is signed and pushed to the registry. Only signed images can be deployed.
  5. The deployer pulls the signed image and rolls it out. Hover any stage for its numbers.

2 · Progressive rollout

Canary, then everyone

  1. Today every request goes to version 1, spread across three replicas.
  2. Version 2 starts as a canary: the load balancer sends it 5% of the traffic.
  3. Metrics compare the canary with the baseline: error rate and latency, for ten minutes.
  4. If the canary holds, the analysis promotes it; if not, the same path rolls it back.
  5. Version 2 now takes all the traffic, and version 1 is drained and retired.
